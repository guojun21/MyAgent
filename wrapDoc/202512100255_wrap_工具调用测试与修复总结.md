# 对话总结：工具调用测试与修复

## 一、主要主题和目标

### 1.1 前后端启动与接口联调
- **目标**：确保 backend_core(8000) 与 frontend(11242) 正常启动并互通
- **需求**：修正 Postman/Newman 测试基址、重新跑健康检查与基础聊天场景

### 1.2 工具调用链路修复
- **目标**：确认 Agent 真正执行 run_terminal 等工具并把结果透传给前端
- **需求**：修复后端字段不匹配、Planner 工具识别错误、验证 tool_calls 在响应和上下文中可见

### 1.3 自动化测试体系建设
- **目标**：补齐缺失的单测/集成测试，覆盖 TerminalService、CodeService、ToolManager、API 端到端调用
- **需求**：新增 pytest 目录结构、fixtures、慢速集成测试；提供运行脚本与依赖

## 二、关键决策和原因

| 决策 | 原因 |
|------|------|
| API 基址统一为 `http://localhost:8000` | backend_core 实际监听 8000，旧配置 11241 导致所有调用失败 |
| routes.py 同时读取 `tool_calls_history` 与 `tool_calls` | AgentLoop 返回的是 `tool_calls`，必须兼容旧字段避免上下文缺数据 |
| Planner 阶段 only expose `planner` 工具 | `get_tool_definitions` 没有 `plan_tool_call`，继续强制旧名称会让 LLM 只输出文本不触发函数调用 |
| 引入 pytest 单测 + 集成测试 | Postman 只能验证 HTTP 200，无法证明工具被执行，需要代码级断言保障 |
| 新建 `tests/requirements-test.txt` 与 `pytest.ini` | 统一依赖与 runner 配置，方便一键运行 |

## 五、解决的问题

### 5.1 Newman 全量失败
- **问题**：Postman collection 仍指向 11241，导致 ECONNREFUSED
- **解决方案**：更新 `baseUrl` 并重新运行 newman（健康检查、聊天、工具命令均通过）
- **结果**：CLI 测试恢复，能作为 smoke 套件

### 5.2 工具调用缺失
- **问题**：API 返回 `tool_calls: []`，前端看不到执行日志
- **解决方案**：1) routes.py 兼容字段 2) Planner 只暴露 `planner` 工具 3) 验证 LLM 真触发 run_terminal
- **结果**：tool_calls 内含 plan/run_terminal/summarize 三段链路

### 5.3 测试缺口
- **问题**：无自动化单测，无法在不跑 LLM 情况下验证基础服务
- **解决方案**：新建 pytest 基础设施 + 42 个单元测试 + 8 个集成测试
- **结果**：`pytest tests/unit/ tests/integration/test_api_tool_calls.py` 共 50 个用例全部通过

## 六、未解决的问题/待办事项

1. **工具调用数据结构统一**：当前历史中同时存在 `tool`, `name`, `function` 三种写法；需定义统一 schema（中优）
2. **慢速集成测试耗时**：LLM 轮训 ~10s，可考虑 mock LLM 或分层执行（低优）
3. **更多工具覆盖**：目前重点在 run_terminal，尚未验证 file_operations 的读写链路（中优）
